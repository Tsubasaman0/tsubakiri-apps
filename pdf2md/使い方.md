# PDF → Markdown

PDF、そして画像(PNG/JPG)をMarkdownに変換する、自分用のアプリ。
ネットにはつながらない。ファイルはこのMacの中だけで処理される。

道具は2つ。

| やりたいこと | 使うもの |
|---|---|
| PDFをMarkdownにしたい | `index.html`(ブラウザで開く) |
| 写真・スクショ(PNG/JPG)をMarkdownにしたい | `PNGフォルダ→Markdown.command`(フォルダをドラッグ) |

## PDFの使い方

1. `index.html` をダブルクリック(ブラウザが開く)
2. PDFをドラッグ&ドロップ
3. Markdownが出てくる
4. 「コピー」か「.md で保存」

保存すると、元のPDFと同じ名前で `.md` ファイルがダウンロードフォルダにできる。
そのままObsidianに放り込める。

画面のテキストは直接その場で書き直せる。直してから保存・コピーしてもいい。

## 4つのスイッチ

| スイッチ | 何をするか |
|---|---|
| 見出しを自動でつける | 文字が大きい行を `#` `##` `###` にする |
| ヘッダー・フッター・ページ番号を消す | 全ページに繰り返し出てくる文字と、ページ番号を捨てる |
| 途中で切れた行をつなぐ | 折り返しで切れた行を1つの段落に戻す。オフにすると1行ずつそのまま出る |
| ページの区切り線を入れる | ページの変わり目に `---` を挟む |

切り替えるとその場で作り直す。PDFを読み直す必要はない。

## できること・できないこと(PDF)

できる:

- 見出し(文字の大きさで4段階まで見分ける)
- 箇条書き(`・` `•` `1.` `①` などの記号つき。記号がなくても、字下げされた短い行が続いていれば拾う)
- 段落の復元(日本語と英文で判定を変えている)
- ヘッダー・フッター・ページ番号の除去
- 太字を重ね描きで表現しているPDFの文字化け(「踏踏んだんだ」)の修復
- 漢字が部首記号の文字コードで入っているPDFの修復(「⻑」→「長」)

できない:

- **紙をスキャンしたPDF**(文字が画像になっているもの)。文字が1つも取れないので、その旨が表示される。→ 下の「PNGの使い方」を使う
- 表。セルの区切りは失われ、1行の文章になる
- 太字・斜体・リンク先URL。文字だけを取り出している
- パスワードつきPDF。先に解除が必要

## PNGの使い方

写真で撮った資料、スクリーンショット、スキャンしたPDFを開いてスクショしたものなど、
**文字が画像になっているもの**はこちら。macOS標準の文字認識(Vision)を使う。

1. 変換したいPNG(またはJPG)を1つのフォルダにまとめる
2. そのフォルダを `PNGフォルダ→Markdown.command` にドラッグ&ドロップ
3. ターミナルの黒い画面が開いて、読み終わると「できました」と出る
4. 同じフォルダの中に `フォルダ名.md` ができている(Finderで自動的に選択される)

ファイル名の順番(page1, page2, page3…)どおりに1つのMarkdownへまとめる。
「page2」より「page10」を後にする、数字としての並び順で読む。

初回だけ、macOSが「開発元を確認できません」と出ることがある。
その場合は `PNGフォルダ→Markdown.command` を右クリック→「開く」を選ぶ。

### できること・できないこと(PNG)

できる:

- 見出し・箇条書き・段落の復元(文字の大きさから判定。PDF版と同じしくみ)
- ヘッダー・フッター・ページ番号の除去(3枚以上のときだけ)
- 複数の画像を1つのMarkdownにまとめる
- 縦にとても長い画像(スクロール画面をつなげたスクショ等)も、分割して読む

できない・PDF版より弱いところ:

- **見出しの判定がPDF版より粗い。** PDFは正確な文字サイズの数値を持っているが、
  画像は「認識した文字の枠の高さ」から見出しかどうかを推測するしかない。
  そのため「4. 問い合わせ先」のような番号つきの短い見出しが、
  箇条書きの続きとして扱われてしまうことがある
- 手書き文字・かすれた文字・斜めに傾いた写真は認識精度が落ちる
- 表・太字・斜体は再現できない(PDF版と同じ)

## 中身

| ファイル | 何か |
|---|---|
| `index.html` | **PDF版の本体**。これだけで動く。1.4MB |
| `PNGフォルダ→Markdown.command` | **PNG版の入り口**。フォルダをドラッグする先 |
| `src/app.html` | PDF版に手を入れるときはこっち。pdf.jsが入っていない素の状態 |
| `src/build.py` | `app.html` + `src/vendor/` → `index.html` を作る |
| `src/vendor/` | pdf.js(Mozilla製、Apache-2.0)。ダウンロード済みの部品 |
| `ocr/ocr-folder.swift` | PNG版の中身(ソースコード) |
| `ocr/bin/ocr-folder` | ↑をコンパイルした実行ファイル。`.command` から呼ばれる |

直したいときは `src/app.html` を編集して、下のコマンドを実行する(PDF版)。

```bash
cd pdf2md && python3 src/build.py
```

PNG版(`ocr-folder.swift`)を直したときは、コンパイルし直す。

```bash
cd pdf2md/ocr && swiftc -O ocr-folder.swift -o bin/ocr-folder
```

### なぜ pdf.js が古い版(3.11)なのか

最新の4系はファイルを分けて読み込む作りで、ダブルクリック(`file://`)で開くと
ブラウザの制限に引っかかる。3系は1つのHTMLに丸ごと埋め込める形なので、
「1枚のファイルで、ネットなしで、ダブルクリックで動く」を満たせる。
PDFから文字を取り出す用途では3系で足りている。

## 動作確認したこと(2026年8月24日)

PDF版:

- ダブルクリック(`file://`)で開いて変換できる
- 日本語のPDF(3ページ・見出し・箇条書き・ヘッダー・ページ番号つき)→ 元の構造どおりに復元
- 英語のPDF(Webページを保存したもの)→ 段落が正しくつながる
- 30MBのPDF → 0.9秒
- 保存したファイルの中身が画面の表示と完全に一致

PNG版:

- `.command` にフォルダをドラッグする形で、実際に画像4枚→1つのMarkdownに変換できた
- 日本語の資料(3ページぶんの画像)→ 見出し・箇条書き・段落・ヘッダー除去まで再現(1ページ約1秒)
- 実際の書籍PDFのページ画像でも文字を正しく抜き出せた
- 2442×26,000ピクセルという極端に縦長の画像(スクロール画面をつなげたスクショ)でも、
  自動でタイル分割して読み切る(最初は文字が小さくなりすぎて失敗したため、方式を直した)
- 保存名がかぶるときは「(2)」を付けて上書きしない
- 画像が1枚もないフォルダ、フォルダではないものをドロップしたとき、それぞれ日本語で案内が出る
